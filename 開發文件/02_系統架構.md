## 1. 一張圖看懂

```
                     ┌────────────────────────── TRON 鏈上 ──────────────────────────┐
                     │                                                                │
 玩家瀏覽器 ─────────▶│  資金合約（所有的錢都在這裡，用帳本分戶）                        │
 （前端網站）         │    ├ 玩家餘額戶（只有本人能扣）                                  │
     │               │    ├ 各期暫存戶（每期分開，定案前錢不能離開）                       │
     │ ①③ 下注       │    ├ 各桶頭獎彩池戶                                              │
     │ （呼叫資金合約）│    ├ 平台戶（收平台份額、付固定獎金）                              │
     │               │    └ 推廣夥伴戶                                                  │
     │ ② 一般轉帳     │                                                                │
     │ （轉到彩金桶地址）│  彩金桶合約 539 ／ 加州（遊戲規則；② 收款地址）                   │
     │               │  預言機合約（開獎結果簽名驗證、爭議）                               │
     │               └──────────────────────────▲─────────────────────────────────────┘
     │                                          │
     │        ┌──────────────┬──────────────────┼──────────────┬──────────────┐
     │        │ 預言機伺服器×3 │     入帳服務      │   排程服務    │  管理多簽錢包  │
     │        └──────────────┴──────────────────┴──────────────┴──────▲───────┘
```

**一句話**：錢全部在資金合約裡，用帳本分戶記清楚；玩家餘額只有玩家本人能扣。鏈下服務負責兩件事：把外面的資料送進來（開獎號碼、轉帳配對），以及觸發結算。每個鏈下服務能做的事，都被合約寫死的規則限制住。

## 2. 關鍵架構決策

| # | 決策 | 原因 |
|---|---|---|
| D1 | **合約不可升級**。新版本另外部署新的彩金桶合約，舊版停收新注、照常結算到結束 | 可升級合約等於「平台 48 小時後什麼都能改」，「平台動不了玩家的錢」這句話就不成立。代價是發現問題時不能原地修，要靠上線前審計與「停收新注」開關 |
| D2 | **只有 3 個合約**：資金合約、彩金桶合約（每桶一個）、預言機合約。平台金庫與推廣分潤併入資金合約，成為帳本裡的戶頭 | 跨合約搬 USDT 每次約 65,000 energy；改成帳本記帳後幾乎不搬錢。合約少，審計範圍也小 |
| D3 | **玩家餘額只有本人能扣** | 彩金桶合約只能動「自己那一期的暫存戶」、「自己的頭獎彩池戶」和「平台戶」。新增或換掉彩金桶合約，也碰不到玩家餘額 |
| D4 | **每期的錢分開記；一期定案前，那期的錢一律不能離開** | 平台份額、推廣分潤、頭獎提撥，都在該期定案時才入帳。進入退款模式時，錢一定都還在 |
| D5 | **柱單用「位元遮罩」儲存，一張柱單一個儲存格** | 39 個號碼用 39 個位元表示，與地址、下注方式合併成一格。「中幾碼」就是兩個遮罩做 AND 後數 1 的個數，運算最省 |
| D6 | **結算在鏈上分批執行，任何人都能觸發** | 中獎完全由合約計算；排程服務停擺時任何人都能代按 |
| D7 | **② 登記與轉帳儲值入帳，要檢查「未入帳餘額」並設金額上限** | 合約記一本「已入帳總額」，登記時要求「實際 USDT 餘額 − 已入帳總額 ≥ 這筆金額」，所以入帳服務無法憑空造錢。但它**能決定錢記給誰**，所以另外設每筆與每小時的入帳上限，並由後台告警逐筆比對（見 4.3） |
| D8 | **每期建立時鎖定當期參數**（每注金額、獎金、頭獎提撥比例、分潤比例；參數只能由管理多簽設定，建期時由合約複製） | 參數調整只影響之後新建立的期別 |
| D9 | **提領永遠不暫停** | 緊急停止開關只停新下注；黑名單也只擋新下注 |
| D10 | **合約時間一律用 UTC** | 539（UTC+8）和加州（有夏令時間）時區不同，換算由建立期別時處理 |
| D11 | **期別時間由合約硬規則把關**：截止（收單）= 開獎 − 10 分鐘，是唯一的收單時間，② 登記也必須在截止前完成；開獎結果簽的官方開獎時間，必須等於該期存的開獎時間 | 防止「開獎後還能下注」的期別。時間對不上的期別一律退款，攻擊者拿不到好處 |
| D12 | **取消、延期都只能在截止前**；截止後唯一的退款路徑是「逾時」 | 防止平台看完開獎號碼後讓整期作廢 |
| D13 | **① ③ 的獎金一律記入餘額，不另外「按領獎」**；② 的獎金每個地址每期合併成一筆，自動轉回錢包 | 約 51.7% 的柱單會中獎（中 1 碼 40.3%、中 2 碼 10.4%…），一張張領太麻煩，也太耗 energy |

## 3. 鏈上合約

| 合約 | 數量 | 負責 | 持有的 USDT |
|---|---|---|---|
| **資金合約** | 1 個 | 帳本（玩家餘額、各期暫存、頭獎彩池、平台、推廣夥伴）；① ③ 下注扣款；授權儲值、轉帳儲值入帳；提領；推廣綁定與分潤 | 幾乎所有的錢 |
| **彩金桶合約** | 每桶 1 個（同一份程式碼） | 期別、柱單、② 登記、接收開獎結果、分批結算、算出各戶應入帳的金額 | 只有 ② 轉進來、還沒登記的錢（登記當下即轉入資金合約） |
| **預言機合約** | 1 個（各桶共用） | 管理 3 個簽名者；驗證開獎結果簽名；爭議處理 | 無 |

### 3.1 帳本與資金流向

**授權對象只有一個：資金合約。** 玩家只需授權一次，539 和加州兩個桶都能用。

| 下注方式 | 下注當下 | 該期定案時（帳本內轉帳） |
|---|---|---|
| ① 授權下注 | 資金合約從玩家錢包扣 USDT → 記入該期暫存戶（**唯一一次搬 USDT**） | 暫存戶 → 頭獎彩池戶（提撥）、推廣夥伴戶（分潤）、平台戶（其餘） |
| ② 轉帳下注 | 玩家轉到彩金桶地址 → 入帳服務登記，**登記當下**彩金桶把這筆 USDT 轉入資金合約 → 記入該期暫存戶 | 同上 |
| ③ 餘額下注 | 玩家餘額戶 → 該期暫存戶（**完全不搬 USDT**） | 同上 |

> ① 其實就是「存入剛好的金額，同時用餘額下注」，在同一筆交易內完成，所以 ① 和 ③ 共用同一段扣款程式。

### 3.2 獎金怎麼付（每期淨額結算）

1. 全期比對完成後，依序：先把本期暫存分配到頭獎彩池（提撥）、分潤待撥、平台戶；再算出**頭獎總額**（彩池含本期提撥 × 80%）與**固定獎金總額**，各自一次移入該期的「頭獎預留」與「固定獎金預留」戶，避免「先算到的人拿現金、後面的人拿欠條」，也避免預留的錢被提走或被下一期算進去。
2. 派發只從這兩個預留戶撥出：固定獎金預留來自平台戶（已含本期平台份額），頭獎預留來自頭獎彩池。推廣分潤也分批從分潤待撥撥入各夥伴戶。
3. 入帳方式：
   - ① ③：記入玩家餘額。
   - ②：記入餘額後，排程服務把每個地址當期的獎金合併成一筆，自動轉回錢包。轉帳失敗（例如收款地址被 USDT 凍結）就留在餘額，不影響其他人。
4. **平台戶不足時**：這期固定獎金整批列為「待付」（頭獎照常派發），後台立即告警；平台注資後由排程服務觸發「補做預留」，成功後一次派發。任何期別處於待付時，平台不得從平台戶提款。

### 3.3 每期的狀態

```
已建立 → 開放下注（可改單、取消） → 已截止（收單） → 已開獎（爭議窗口） → 結算中 → 已定案
   │          │                                 │
   └─ 取消／延期（只能在截止前）                    └─ 開獎後 72 小時仍未定案 ──▶ 退款模式
```

| 狀態轉換 | 誰觸發 | 合約檢查 |
|---|---|---|
| 建立期別 | 排程服務或管理多簽（手動補建） | 開獎時間至少在 1 小時後；參數由合約複製現行設定，呼叫者不能自帶；截止時間由合約依 D11 自動算出，不能自填；同一桶最多同時存在 2 個未截止的期別 |
| 取消／延期 | 管理多簽 | 只能在截止前。延期後的開獎時間同樣受 D11 規則限制 |
| 改單／取消 | 玩家本人 | 只能在截止前；改單＝同金額換號碼（更新該柱單的位元遮罩）；取消＝該期暫存戶 → 玩家餘額 |
| 截止 | 自動（依區塊時間） | ① ③ 下注、② 登記、改單、取消一律被拒 |
| 寫入開獎結果 | 任何人（帶簽名） | 區塊時間晚於開獎時間；簽名內的官方開獎時間等於該期存的時間（不符 → 該期進入退款模式） |
| 爭議處理 | 見 3.5 | — |
| 分批結算、定案 | 任何人 | 爭議窗口已結束且無爭議 |
| 進入退款模式 | 任何人 | 開獎時間後超過 72 小時仍未定案 |

**退款模式**：該期所有柱單金額，從該期暫存戶原數退回玩家餘額（①②③ 都一樣）。② 的玩家可以一鍵提領，由平台代付 energy、不需要授權。因為 D4 規定定案前錢不能離開，所以退款的錢一定都在；推廣分潤也不會發生。

### 3.4 結算怎麼算

1. **分批比對**：每批處理 N 張柱單，算出每張中幾碼。合約只累計「中 1／2／3／4／5 碼各幾張」，**不另外存中獎名單**，避免有人大量買同一組號碼時把結算灌爆。N 以實測執行時間為準，並保留大幅餘裕（TRON 單筆交易有 80 毫秒執行上限）。
2. **定案**：算出最高碼數與張數、每張頭獎金額、4 碼保底獎張數、滾存金額，執行 3.2 的淨額入帳。
3. **派發**：再分批走一次，依每張柱單的中碼數入帳；② 的地址合併後自動轉回。

### 3.5 預言機與爭議

- **3 台獨立伺服器**放在不同雲端業者，私鑰各自保管。備援資料來源使用**另一套解析程式**，避免官網改版時 3 台同時出錯。
- **期別建立**：由排程服務送出，但受 D11 硬規則限制（不需要預言機簽名）。
- **開獎結果**：每台對「桶別＋期號＋5 個號碼＋官方開獎時間」簽名。
  - **3 台中 2 台一致即可提交。** 爭議窗口 30 分鐘內，第 3 台若沒有提出不同結果，窗口結束後自動成立。
  - **只有 3 台不一致時才需要人**：任何一台在窗口內提交不同結果，該期就進入「爭議中」，由管理多簽裁定。
  - **否決每期最多一次**；否決後須 3 台全部一致才能重新提交。
  - 這樣管理多簽不必每天開獎後在線待命，只在出現分歧時才需要處理。
- 簽名者更換須經管理多簽核准，並等待 48 小時才生效。

### 3.6 ② 轉帳下注在鏈上怎麼成立

1. 玩家在前端選號，錢包**簽署一般訊息**（不用 TIP-712；TIP-712 目前只有 TronLink 支援）。訊息內容：桶別、期號、號碼組、金額、推廣碼、建立時間。待付單存在入帳服務的資料庫。
2. 玩家用一般轉帳把 USDT 轉到彩金桶地址。錢包送出後，前端當下就拿到交易編號，立即回報入帳服務，**「待付單 ↔ 交易編號」精確綁定**。只有在玩家關掉瀏覽器時，才退回用「同地址、金額、時間」配對。
3. 入帳服務等轉帳所在區塊**不可逆**（約 19 個區塊，約 1 分鐘），再呼叫合約登記。
4. 合約檢查以下幾點，全部通過才登記柱單：
   - 簽名屬於待付單上的玩家地址
   - 這張待付單沒有用過（以待付單內容雜湊標記）
   - 現在時間早於截止（收單）時間
   - 未入帳餘額足夠（D7），且未超過入帳上限
5. **異常、漏登、截止後才到帳的轉帳**：一律走同一條路，由入帳服務轉記為該地址的玩家餘額（同樣受 D7 限制）。入帳服務停擺超過 6 小時，由管理多簽代為執行。

> **② 唯一剩下的信任環節**：合約無法從鏈上讀到「這筆轉帳是誰轉的、何時轉的」，「轉帳者 = 簽名者」與「轉帳早於截止」都由入帳服務比對。任何人都可以拿公開的轉帳紀錄核對。合約擋得住的期限就是截止（收單）時間，早於官方開號，所以沒有人能在知道號碼後下注。網站在截止前 5 分鐘停止接受 ② 下單（539 為 20:15），留時間給區塊確認與登記；來不及登記的轉帳轉入玩家餘額。

## 4. 鏈下服務

### 4.1 服務清單

| 服務 | 負責 | 被合約限制住的範圍 | 停擺時的影響 |
|---|---|---|---|
| **前端網站** | 連接錢包、選號、三種下注、會員中心、歷史紀錄、推廣頁、多語系（英／繁中／簡中） | 只能送玩家自己簽名的交易 | 玩家可以直接用區塊鏈瀏覽器呼叫資金合約提領 |
| **鏈上資料索引服務** | 監聽事件、寫入資料庫，提供歷史紀錄、跑馬燈、報表 API | 只讀 | 歷史頁空白，不影響資金 |
| **入帳服務** | ② 待付單綁定與登記、異常轉帳轉餘額、轉帳儲值入帳 | D7 檢查與入帳上限；無法提領任何資金 | ② 與轉帳儲值暫停入帳；超過 6 小時由管理多簽代為執行 |
| **排程服務** | 建立期別、觸發分批結算與派發（含推廣分潤撥入）、② 自動轉回、平台注資後觸發補做預留、逾時期別觸發退款並分批退完、監控 energy | 期別時間受 D11 限制；其他都是公開功能 | 結算延後，任何人可代為觸發 |
| **預言機伺服器 ×3** | 讀取官方結果、簽名、提交 | 2 台一致才能提交；分歧時進入爭議 | 72 小時未定案即退款 |
| **後台網站** | 跑馬燈、公告、期別管理、各服務監控、報表；合約操作會產生待簽交易，交給管理多簽簽署 | 後台本身沒有合約權限 | 無法改內容，不影響遊戲 |

### 4.2 資料放哪裡

| 鏈上 | 鏈下（資料庫） |
|---|---|
| 柱單、期別、開獎結果、帳本各戶餘額、推廣綁定 | 跑馬燈、公告與常見問題文案、玩家收藏號碼、② 待付單與玩家簽名、各服務日誌、客服紀錄 |

### 4.3 入帳服務被盜時的損失上限

入帳服務**能決定錢記給誰**，只是不能憑空造錢。被盜時，攻擊者最多能把「當下還沒登記的轉帳」記到自己名下。這個範圍用以下方式壓到最小：

| 措施 | 效果 |
|---|---|
| 每筆與每小時入帳上限（合約參數）【待定】 | 單位時間內最多能被偷的金額有上限 |
| 後台告警逐筆比對交易編號 | 幾分鐘內發現異常，由管理多簽暫停入帳服務權限（提領照常） |
| 無主款定期清理（見 4.4） | 未入帳餘額平常接近 0 |

### 4.4 無主款

從交易所轉入、沒有任何待付單可對應的錢，會變成「未入帳餘額」。

- 平台先公告並開放人工認領（玩家用原轉帳錢包簽名證明）。
- 超過 30 天仍無人認領，由管理多簽掃進平台戶，該操作須等待 48 小時並公開。

### 4.5 收單報表時間

每期的收單報表在截止（539 為 20:20）後匯出；此時 ② 已全部登記完畢，報表完整。

## 5. 權限與金鑰

| 角色 | 形式 | 能做什麼 | 不能做什麼 |
|---|---|---|---|
| **管理多簽** | 多簽錢包（3 取 2 或 5 取 3【待定】） | 調參數（只影響新期別）、手動建立期別、截止前取消或延期、更換或停用入帳服務與排程服務錢包（立即生效）、爭議裁定（每期否決一次）、黑名單、停收新注、新增彩金桶合約（等待 48 小時）、平台戶提款（有期別待付時不得提款）、入帳服務停擺時代為入帳、無主款清理（等待 48 小時） | 扣玩家餘額、改柱單、直接寫開獎號碼、截止後取消期別、升級合約 |
| **預言機簽名者 ×3** | 各自獨立私鑰 | 對開獎結果簽名 | 單獨一台無法讓結果成立 |
| **入帳服務錢包** | 伺服器熱錢包（管理多簽可隨時更換或停用） | 登記 ② 柱單、轉帳轉餘額 | 超過未入帳餘額或入帳上限、提領任何資金 |
| **排程服務錢包** | 伺服器熱錢包（管理多簽可隨時更換或停用） | 建立期別 | 違反 D11 時間規則、自帶期別參數 |
| **energy 代付帳戶** | 部署合約的帳戶 | 提供玩家呼叫合約時的 energy | 無管理權限 |

**energy 代付**：合約部署時設定由部署帳戶支付 100% energy，玩家只付 bandwidth。

為了防止有人故意呼叫公開功能來消耗平台的 energy：
- 每個合約的單筆 energy 上限設緊。
- 公開功能先做最便宜的檢查，不符合就盡早拒絕。

部署帳戶 energy 不足時，差額會轉由玩家燒 TRX，所以排程服務要監控存量並告警。

**對玩家揭露的集中風險**：USDT 發行方可以凍結任何地址，包括本專案的資金合約。這是使用 USDT 的固有風險，需在遊戲規則中揭露。
