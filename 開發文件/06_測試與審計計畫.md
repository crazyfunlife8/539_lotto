## 1. 原則

1. **測試分兩條線**：
   - **經濟模擬**：驗證「算錢」對不對、平台扛不扛得住。
   - **合約與系統測試**：驗證「程式」有沒有寫錯。
2. **開獎號碼來自官方彩券，本專案不自行產生亂數**，所以一般博弈遊戲的亂數認證不適用。中獎機率是固定的組合數學，模擬的重點放在公式算不出來的「波動」與「集中」風險。
3. **AI 負責撰寫測試、執行模擬、做內部程式審查；第三方審計由審計公司執行，不由 AI 取代。** 所有測試都是可重複執行、結果固定的程式。
4. 每個測試階段都有明確的「通過門檻」，未通過不得進入下一階段。

## 3. 經濟模擬（T5）

### 3.1 輸入

- `03_經濟模型試算.xlsx` 的全部參數（每注金額、各級獎金、頭獎提撥、推廣分潤、上游成本與派彩、下注方式比例）。
- T4 實測的 energy 數值。
- 兩種「沒人中頭獎」方案（`noWinnerRule`）。

### 3.2 模擬情境

| 變數 | 情境 |
|---|---|
| 每期柱單數 | 500、1,000、3,000、5,000、10,000 |
| 玩家選號分布 | ① 完全隨機 ② 偏好 1–31（生日號碼）③ 少數熱門號碼高度集中 |
| 推廣分潤 | 無推廣人／全部柱單都付滿兩層分潤（假設玩家自己推廣自己） |
| 下注方式比例 | 以 ① ② ③ 不同比例組合（影響 energy 與自動轉回成本） |

每組情境模擬 **至少 100,000 期**。

### 3.3 輸出

| 指標 | 用途 |
|---|---|
| 平台每期損益的平均值與分布 | 確認長期有利潤 |
| 最差連續 N 期的累積虧損（N = 7、30、90） | 決定平台戶的週轉金水位與告警門檻 |
| 單期最大固定獎金支出 | 決定「平台戶低於預警水位」的數字 |
| 玩家回報率（RTP） | 對照國際鏈上彩票（對標研究：Megapot 約 77.5%、CryptoDrawz 約 90%） |
| 頭獎彩池規模走勢、平均幾期派出一次 | 比較兩種 `noWinnerRule` |
| 選號集中時的單期虧損放大倍數 | 判斷是否需要「單一號碼組合下注上限」 |

### 3.4 通過門檻【待定】

由業主依模擬結果決定，至少包含：
- 長期平均淨利率下限
- 在選定週轉金水位下，平台戶不足的機率上限
- 若選號集中情境的虧損超出可承受範圍，必須新增「單一號碼組合下注上限」規則（回寫 PRD 與合約規格）後重跑。

## 4. 合約單元測試（T1）

每個函式都要涵蓋「正常」「每一項檢查不通過」「邊界值」三類案例。重點邊界：

| 類別 | 必測案例 |
|---|---|
| 時間 | 截止前 1 秒可下注、改單、取消、② 登記；截止當秒與之後全部拒絕；`createPeriod` 開獎時間不足 1 小時被拒；未截止期別已達 2 期時建期被拒 |
| 號碼 | 遮罩不是剛好 5 個位元、用到第 39 位以上一律被拒；號碼 1 對應第 0 位、號碼 39 對應第 38 位 |
| 中獎判定 | 0–5 碼各情況；最高碼數為 5 時，4 碼改領保底獎；多人同中平分、除不盡的零頭留在彩池；沒人中時兩種 `noWinnerRule` |
| 金流 | ① 授權不足、③ 餘額不足；USDT 回傳值不標準時以餘額差判斷（V8）；轉入金額以餘額差入帳（V9） |
| 改單／取消 | 非柱單主人被拒；已取消的柱單不能再改；取消後推廣應得被扣回、金額退回餘額 |
| ② 登記 | 簽名錯誤、待付單重複使用、金額與張數不符、未入帳餘額不足、超過入帳上限、黑名單、停收；首次用 ② 下注會綁定推廣人並累加分潤，取消 ② 柱單時扣回 |
| 推廣 | 首次下注綁定；之後帶不同推廣人不改變；推廣人是自己或零地址視為沒有；第二層正確；三種下注方式都會綁定；分潤在定案後分批撥入、退款期別不產生分潤 |
| 異常轉帳 | 未入帳餘額不足時拒絕；成功時記入玩家餘額 |
| 預言機 | 只有 1 個簽名被拒；號碼重複或超出範圍被拒；簽名內開獎時間與期別不符 → 退款中；爭議、裁定、否決一次後須 3 簽一致 |
| 結算 | 分批處理到最後一批；定案時 I4 平衡；頭獎計算含本期提撥（第一期彩池為 0 時仍有頭獎）；定案後頭獎與固定獎金移入預留戶、平台無法提走；平台戶不足 → 固定獎金待付、頭獎照常派發；注資後 `retryReserve` 解除待付，注資不足仍待付；`noWinnerRule` 兩種情況 |
| 退款 | `expire` 在 72 小時前被拒、之後成功；取消、延期在截止後被拒；期別取消後下注、改單、取消柱單一律被拒；已退款的柱單不能再取消或退款（I8） |
| 權限 | 每個限定呼叫者的函式都測「錯誤呼叫者被拒」；未啟用的 `Pool` 呼叫 `Vault` 被拒；新增 `Pool` 未滿 48 小時無法啟用；排程服務不能自帶期別參數；`setParams` 後已建立期別的參數不變；更換或停用入帳服務、排程服務錢包後，舊錢包呼叫被拒；入帳服務停擺未滿 6 小時多簽代為入帳被拒 |
| 提領 | 停收、黑名單狀態下仍可提領 |
| 自動轉回 | 只能轉給本人；轉帳失敗時錢留在餘額、不影響其他人；玩家先提領後才觸發自動轉回時，只轉剩餘金額、標記清零 |

## 5. 合約隨機壓力測試（T2）

- 由測試程式隨機產生操作序列：多個玩家、多個期別，交錯執行下注（①②③）、改單、取消、時間前進、建期、開獎、爭議、分批結算、派發、退款、提領、儲值、異常轉帳、推廣領取、平台注資與提款。
- **每一步之後**檢查智能合約規格 1.3 的不變式 I1–I8，任何一次違反即為缺陷。
- 規模：至少 200,000 組序列，每組數十到數百步。
- 本地測試工具：以 EVM 相容的測試框架執行【實作查證：TRON 合約的本地測試工具選擇】；**TRON 專屬行為**（USDT 回傳值、energy、bandwidth）一律在 Nile 測試網補測。

## 6. 鏈下服務測試（T3）

| 服務 | 必測案例 |
|---|---|
| 入帳服務 | 前端回報交易編號的精確綁定；前端未回報時退回金額與時間配對；轉多、轉少、無待付單、截止後到帳、低於一注金額累積；等待不可逆區塊後才登記；服務重啟後不重複登記；入帳上限觸頂時排隊而不遺失 |
| 預言機伺服器 | 官方資料正常；官方網站改版或無回應時切換備援來源；3 台結果分歧時觸發爭議；春節加開與天災改期的期號處理；加州夏令時間切換（第二版） |
| 排程服務 | 依官方期號只預建下 1–2 期；結算、派發（頭獎、固定獎金、推廣分潤）、自動轉回中途中斷後可續跑；逾時與取消的期別自動完成分批退款；平台注資後自動觸發補做預留；energy 低於水位時告警 |

| 後台 | 每種待簽交易產生正確；後台帳號無法直接觸發任何合約操作；告警 8 項全部可觸發並推送 Telegram；收單報表 20:20 後匯出完整 |

## 7. 測試網整期模擬（T6）

在 Nile 測試網用機器人帳號連續跑多期，每期包含三種下注方式、改單與取消。以下情境每個至少跑一次：

| # | 情境 | 預期結果 |
|---|---|---|
| S1 | 正常一期 | 結算正確、①③ 獎金入餘額、② 自動轉回、推廣分潤入帳 |
| S2 | 20:15 後送出 ② 轉帳 | 前端已停止；若仍轉入 → 轉入玩家餘額 |
| S3 | 截止前改單、取消 | 號碼更新、取消金額退回餘額、分潤扣回 |
| S4 | 預言機 1 台故障 | 另 2 台照常提交 |
| S5 | 預言機結果分歧 | 進入爭議 → 多簽裁定 |
| S6 | 開獎後 72 小時仍未定案 | 排程服務觸發退款並分批退完；全額退回餘額、無推廣分潤 |
| S7 | 截止前取消期別 | 全額退回餘額 |
| S8 | 平台戶不足 | 整期固定獎金待付 → 注資後一次派發 |
| S9 | 入帳服務停擺超過 6 小時 | 多簽代為入帳 |
| S10 | 某中獎地址被 USDT 凍結（以測試代幣模擬） | 自動轉回失敗、錢留在餘額、其他人正常 |
| S11 | 無主款 | 認領流程與 30 天清理流程 |
| S12 | 全域停收與黑名單 | 下注被擋、提領正常 |
| S13 | energy 耗盡 | 玩家改為自付 TRX；告警觸發 |
| S14 | 同期有人中 5 碼 | 4 碼柱單領保底獎 |
| S15 | 新增彩金桶合約 | 48 小時後才能啟用 |
