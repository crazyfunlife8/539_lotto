## 1. 總則

### 1.1 技術前提

- 鏈：TRON 主網；測試：Nile 測試網。
- 語言：Solidity（TVM 相容版本，實作時以 TRON 官方編譯器支援的最新穩定版為準）。
- 計價代幣：USDT（TRC20），6 位小數。合約內所有金額以 USDT 最小單位（10⁻⁶）的整數儲存。
- **3 個合約、全部不可升級**（D1、D2）：`Vault`（資金合約）、`Pool`（彩金桶合約，每桶部署一份）、`Oracle`（預言機合約）。

### 1.2 USDT 互動的強制寫法

| 規則 | 原因 |
|---|---|
| 不使用常見的安全轉帳函式庫，改用自訂介面：呼叫後**以餘額變化判斷成功與否**，不依賴回傳值 | TRON 上的 USDT 轉帳回傳值不符合標準，常見函式庫會把成功誤判為失敗（V8） |
| 所有轉入一律以「轉入前後的合約餘額差」入帳 | 防止代幣帶手續費參數時帳不平（V9） |
| 所有對外轉帳採「先改帳、後轉帳」順序 | 防止重入攻擊 |

### 1.3 全域不變式（審計與測試必須逐條驗證）

| # | 不變式 |
|---|---|
| I1 | `USDT.balanceOf(Vault)` ≥ 帳本總額 = 玩家餘額總和 + 各期暫存總和 + 各桶頭獎彩池 + 平台戶 + 推廣夥伴戶總和 + 各期分潤待撥總和 + 各期頭獎預留總和 + 各期固定獎金預留總和（「待自動轉回」只是玩家餘額內的標記，不另外計入） |
| I2 | 玩家餘額只會因「玩家本人的呼叫」而減少；唯一例外是自動轉回（見 2.6），而且錢只能轉到該玩家本人的地址 |
| I3 | 某期定案或退款前，該期暫存戶的錢只會流向玩家餘額（取消柱單、退款）；不會流向其他任何戶頭 |
| I4 | 某期定案時：該期暫存 = 頭獎提撥 + 分潤總額 + 平台份額，分毫不差；定案後暫存為 0 |
| I5 | 截止後、或期別不在「開放」狀態時，該期柱單不會再新增、修改或取消 |
| I6 | 一張待付單（② 訂單）最多成立一次柱單 |
| I7 | `Pool` 持有的 USDT 只有「尚未登記的 ② 轉入款」；登記後立即轉入 `Vault` |
| I8 | 每張柱單最多被「取消」「退款」「派發」其中一種處理一次 |

## 2. 資金合約 `Vault`

### 2.1 帳本戶頭

| 戶頭 | 鍵 | 誰能增加 | 誰能減少 |
|---|---|---|---|
| 玩家餘額 `balance` | 玩家地址 | 儲值、獎金派發、取消退回、退款、異常轉帳入帳、無主款認領 | 玩家本人（下注、提領）；自動轉回（只轉給本人） |
| 期別暫存 `escrow` | 桶＋期 | 下注 | 定案分配（I4）、取消退回、退款 |
| 頭獎彩池 `jackpot` | 桶 | 定案時的提撥 | 定案時移入頭獎預留；沒人中頭獎且 `noWinnerRule` = 2 時移入平台戶 |
| 平台戶 `platform` | — | 定案時的平台份額、平台注資、沒人中頭獎時的彩池轉入、無主款清理 | 定案時移入固定獎金預留；平台提款 |
| 分潤待撥 `partnerPending` | 桶＋期 | 定案時的分潤總額 | 分批撥入各推廣夥伴戶 |
| 推廣夥伴戶 `partner` | 夥伴地址 | 分潤分批撥入 | 夥伴本人領取 |
| 頭獎預留 `jpReserve` | 桶＋期 | 定案時從頭獎彩池移入 | 分批派發給頭獎得主；派完後的零頭退回頭獎彩池 |
| 固定獎金預留 `fixedReserve` | 桶＋期 | 定案或補做預留時從平台戶移入 | 分批派發給中 1–3 碼與 4 碼保底獎得主 |
| 待自動轉回 `autoReturn` | 玩家地址 | ② 柱單的獎金派發時 | 自動轉回成功或失敗時清零。**只是玩家餘額內的標記，不是另一筆錢，不計入帳本總額** |

`Vault` 維護「帳本總額」（上表除 `autoReturn` 外所有戶頭合計），每次入帳、出帳同步更新，供未入帳餘額計算與 I1 檢查。

### 2.2 推廣綁定（①②③ 都適用）

- `referrerOf[player]`：玩家第一次成功下注時寫入，之後不可更改。
- 下注時帶入的推廣人若為自己、或為零地址，視為無推廣人。
- 第二層 = 推廣人的推廣人。
- ① ③ 由 `placeBets` 內部綁定；② 由 `Pool` 在登記時呼叫 `bindReferrer`（2.4）綁定。

### 2.3 玩家功能

| 函式 | 說明 | 檢查 |
|---|---|---|
| `deposit(amount)` | 授權儲值：從錢包扣 USDT 記入餘額 | 金額 > 0；以餘額差入帳 |
| `withdraw(amount)` | 提領到本人錢包 | 餘額足夠。**任何狀態下都不暫停**（D9），黑名單也不擋 |
| `placeBets(pool, periodId, masks[], fromWallet, referrer)` | ① 與 ③ 下注的唯一入口。`fromWallet = true` 為 ①（從錢包扣剛好的金額），`false` 為 ③（從餘額扣） | `pool` 已啟用且未停用；未全域停收；玩家不在黑名單；張數 ≤ 每筆上限；扣款成功後綁定推廣人，再呼叫 `Pool.recordTickets` |
| `claimPartner(amount)` | 夥伴領取分潤到本人錢包 | 夥伴戶足夠 |

### 2.4 給 `Pool` 呼叫的功能（只限已啟用的桶；每個函式只能動呼叫者自己那一桶的戶頭）

| 函式 | 說明 |
|---|---|
| `bindReferrer(player, referrer)` | 規則同 2.2；回傳實際的第一、二層推廣人 |
| `escrowToBalance(periodId, player, amount)` | 取消柱單、退款：暫存 → 玩家餘額 |
| `depositFromPool(periodId, player, amount, asBet)` | ② 登記或異常轉帳：`Pool` 把 USDT 轉入 `Vault`，`Vault` 以餘額差入帳，記入該期暫存（`asBet = true`）或玩家餘額（`false`） |
| `settlePeriod(periodId, toJackpot, partnerTotal, toPlatform)` | 定案分配：暫存 → 頭獎彩池、分潤待撥、平台戶；三者合計必須等於該期暫存（I4），否則整筆失敗 |
| `reserveJackpot(periodId, amount)` | 頭獎彩池 → 頭獎預留 |
| `jackpotToPlatform(amount)` | 沒人中頭獎且 `noWinnerRule` = 2：頭獎彩池 → 平台戶 |
| `reserveFixed(periodId, amount)` | 平台戶 ≥ 金額 → 平台戶 → 固定獎金預留，回傳成功；不足 → 不動帳，回傳「待付」 |
| `payPrize(periodId, player, amount, fromJackpot, autoReturn)` | 頭獎預留或固定獎金預留 → 玩家餘額；`autoReturn = true` 時同時加上待自動轉回標記 |
| `releaseJackpotRemainder(periodId)` | 頭獎派完後，頭獎預留的零頭 → 頭獎彩池 |
| `partnerPendingToPartner(periodId, partner, amount)` | 分潤待撥 → 推廣夥伴戶 |

### 2.4b 給入帳服務呼叫的功能

| 函式 | 說明 | 限制 |
|---|---|---|
| `creditTransferDeposit(player, amount, txRef)` | 轉帳儲值：玩家用一般轉帳轉到 `Vault` 地址的錢，記入玩家餘額 | `Vault` 未入帳餘額（`USDT.balanceOf(Vault)` − 帳本總額）≥ 金額；未超過入帳上限；事件內含 `txRef` |

**入帳服務停擺時的代為入帳**：`Vault` 記錄「入帳服務錢包最後一次成功呼叫的區塊時間」（`Pool` 的入帳函式成功時也透過 `Vault` 更新）。距今超過 `RELAYER_FALLBACK`（6 小時）時，管理多簽也可呼叫 `creditTransferDeposit` 與 `Pool.creditUnmatched`，限制相同。

### 2.5 管理多簽功能

| 函式 | 說明 | 限制 |
|---|---|---|
| `setParams(...)` | 設定現行參數：每注金額、中 1／2／3 碼獎金、4 碼保底獎、頭獎提撥比例、推廣第一／二層比例、`noWinnerRule`、每筆張數上限 | 只影響之後新建立的期別（建期時複製進該期 `params`） |
| `setRelayer(addr)`、`setScheduler(addr)` | 設定、更換入帳服務錢包與排程服務錢包；設為零地址即停用 | **立即生效**（緊急止血用）；`Vault` 與各 `Pool` 都讀這兩個設定 |
| `setRelayerLimits(perTx, perHour)` | 入帳服務的入帳上限 | 數值【待定】 |
| `proposePool(pool)` → `activatePool(pool)` | 登記新的彩金桶合約 | 提案後須等 48 小時才能啟用 |
| `retirePool(pool)` | 該桶停收新注（已開始的期別照常結算） | 立即生效 |
| `setPaused(bool)` | 全域停收新注 | 不影響提領、結算、派發、退款 |
| `setBlacklist(player, bool)` | 黑名單只擋新下注 | 不影響提領與既有柱單 |
| `fundPlatform(amount)` | 平台注資 | — |
| `withdrawPlatform(to, amount)` | 平台提款 | 只能提平台戶本身（固定獎金預留另戶，不受影響）；任何期別處於「固定獎金待付」時不得提款 |
| `proposeSweepUnclaimed(source, amount)` → `executeSweep` | 無主款 → 平台戶；`source` 為某個 `Pool` 或 `Vault` 本身 | 須等 48 小時；受該來源未入帳餘額限制。「30 天未認領」由後台營運規則把關，不在合約內判斷 |
| `creditUnclaimed(source, player, amount)` | 人工認領無主款 → 玩家餘額 | 受該來源未入帳餘額限制 |

### 2.6 自動轉回（給 ② 玩家）

- `pushAutoReturn(player)`：**任何人都能呼叫**。轉回金額 = min（待自動轉回標記, 玩家當下餘額），從餘額轉到**玩家本人地址**。
- 轉帳成功或失敗，都把待自動轉回標記清零。失敗時（例如地址被 USDT 凍結）錢留在餘額、發出失敗事件，不影響其他人。
- 排程服務在每期派發完成後，對每個 ② 中獎地址各呼叫一次（同一地址同期合併為一筆）。

## 3. 彩金桶合約 `Pool`

### 3.1 儲存結構

**期別 `Period`**

| 欄位 | 說明 |
|---|---|
| `officialNo` | 官方期號（例：115000237） |
| `drawTime` | 官方開獎時間（UTC 秒） |
| `cutoff` | `drawTime − CUTOFF_OFFSET`，由合約計算（D11） |
| `params` | 建期當下從 `Vault` 現行參數複製（D8） |
| `status` | 開放／已截止（依時間判斷）／已開獎／爭議中／結算中／已定案／已取消／退款中 |
| `result` | 開獎號碼遮罩 |
| `totalStake` | 本期有效柱單總額 |
| `partnerAccrual[夥伴]`、`partnerList`、`partnerTotal` | 本期各推廣夥伴應得分潤（下注時累加、取消時扣回）與總額 |
| `hitCount[0..5]`、`maxHits` | 各中碼數張數、最高中碼數 |
| `jpPerTicket` | 每張頭獎得主的金額 |
| `fixedPending` | 固定獎金是否待付 |
| 各游標 | 比對、固定獎金派發、頭獎派發、分潤撥入、退款各自的分批進度 |

**柱單 `Ticket`**：一張一個儲存格（256 位元）

| 位元 | 欄位 |
|---|---|
| 0–159 | 玩家地址 |
| 160–198 | 號碼遮罩（39 位元；**號碼 n 對應遮罩第 n−1 位**） |
| 199–200 | 下注方式（① ② ③） |
| 201–202 | 狀態（有效／已取消／已派發／已退款） |
| 203–255 | 保留 |

### 3.2 號碼與中獎判定

- 遮罩必須剛好 5 個位元為 1，且只用到第 0–38 位，否則拒絕。
- 中幾碼 = `popcount(ticket.mask & period.result)`，以位元運算實作（不用迴圈）。

**獎項判定**（每張只領最高一項）：

| 中碼數 | 條件 | 獎金 |
|---|---|---|
| 0 | — | 無 |
| 1／2／3 | — | 該期 `params` 的固定獎金 |
| 5 | 本期最高碼數為 5 | 頭獎：可派頭獎 ÷ 中 5 碼張數 |
| 4 | 本期最高碼數為 4 | 頭獎：可派頭獎 ÷ 中 4 碼張數 |
| 4 | 本期最高碼數為 5 | 4 碼保底獎（固定獎金） |

- **頭獎計算用的彩池 = 既有彩池 + 本期提撥**（定案時先入帳提撥再計算，第一期才不會是 0）。
- 有人中頭獎：可派頭獎 = 彩池 × 80%，其餘 20% 留在彩池；除不盡的零頭派完後退回彩池。
- 沒人中頭獎：`noWinnerRule` = 1 全額留存；= 2 保留 20%，其餘 80% 轉平台戶。**使用哪一個【待定】**，由經濟模型決定。

### 3.3 功能

| 函式 | 呼叫者 | 檢查與動作 |
|---|---|---|
| `createPeriod(officialNo, drawTime)` | 排程服務錢包或管理多簽 | `drawTime ≥ now + MIN_LEAD`；`cutoff` 由合約計算；同一桶未截止的期別 ≤ 2；`officialNo` 未用過；`params` 從 `Vault` 現行參數複製（呼叫者不能自帶） |
| `cancelPeriod(id)` | 管理多簽 | `now < cutoff` 且狀態為開放（D12）→ **已取消** |
| `postponePeriod(id, newDrawTime)` | 管理多簽 | `now < cutoff` 且狀態為開放；新時間受 `MIN_LEAD` 限制；重算 `cutoff` |
| `recordTickets(player, id, masks[], mode, l1, l2)` | 只限 `Vault` | 狀態為開放且 `now < cutoff`；遮罩合法；寫入柱單；累加 `totalStake` 與推廣應得 |
| `registerTransferOrder(order, signature, txRef)` | 入帳服務錢包 | 見 3.4 |
| `creditUnmatched(player, amount, txRef)` | 入帳服務錢包（停擺超過 6 小時後管理多簽也可） | 未入帳餘額 ≥ 金額；未超過入帳上限 → `Vault.depositFromPool(asBet = false)` |
| `editTicket(ticketId, newMask)` | 柱單主人 | 期別狀態為開放且 `now < cutoff`；柱單有效；新遮罩合法；只改號碼、不動金額 |
| `cancelTicket(ticketId)` | 柱單主人 | 期別狀態為開放且 `now < cutoff`；柱單有效 → 已取消；扣回 `totalStake` 與推廣應得；`Vault.escrowToBalance` |
| `submitResult(id, numbers[5], drawTime, sigs)` | 任何人 | 期別不是已取消或退款中；轉交 `Oracle` 驗證；`now ≥ drawTime`；簽名內的 `drawTime` 必須等於該期 `drawTime`，不符 → 退款中 |
| `evaluate(id, n)` | 任何人 | 爭議窗口已過且無爭議；處理接下來 n 張有效柱單，累計 `hitCount` |
| `finalize(id)` | 任何人 | 全部比對完後依序：① `Vault.settlePeriod`（提撥 = `totalStake` × 提撥比例；分潤 = `partnerTotal`；平台份額 = 其餘）② 算頭獎：有人中 → `Vault.reserveJackpot`；沒人中且規則 2 → `Vault.jackpotToPlatform` ③ 算固定獎金總額 → `Vault.reserveFixed`，不足則 `fixedPending = true` ④ 狀態 → 已定案 |
| `retryReserve(id)` | 任何人 | 已定案且 `fixedPending` → 再呼叫 `Vault.reserveFixed`，成功則解除待付 |
| `distributeJackpot(id, n)` | 任何人 | 已定案 → 處理接下來 n 張的頭獎派發；全部派完後 `Vault.releaseJackpotRemainder`。**不受固定獎金待付影響** |
| `distributeFixed(id, n)` | 任何人 | 已定案且未待付 → 處理接下來 n 張的固定獎金派發 |
| `distributePartner(id, n)` | 任何人 | 已定案 → 把接下來 n 位夥伴的應得分潤撥入夥伴戶 |
| `expire(id)` | 任何人 | `now > drawTime + TIMEOUT`（72 小時）且未定案 → 退款中 |
| `refund(id, n)` | 任何人 | 已取消或退款中 → 處理接下來 n 張有效柱單：狀態改已退款、`Vault.escrowToBalance` |
| `projectedJackpot(id)` | 唯讀 | 回傳「目前彩池 + 本期 `totalStake` × 提撥比例」，供前端首頁顯示 |

派發時 ② 柱單帶 `autoReturn = true`，派完的柱單狀態改已派發。

### 3.4 ② 轉帳下注的登記

**待付單 `order` 內容**（玩家用錢包簽一般訊息，格式見 V1）：

| 欄位 | 說明 |
|---|---|
| `pool` | 本桶合約地址 |
| `periodId` | 期別 |
| `masks[]` | 號碼組 |
| `amount` | 總金額 = 張數 × 每注金額 |
| `referrer` | 推廣人（可為空） |
| `nonce` | 前端產生的隨機值 |
| `createdAt` | 建立時間 |

**`registerTransferOrder` 的檢查順序**（先做便宜的檢查，不合格就盡早拒絕，避免耗費平台 energy）：

1. 呼叫者是 `Vault` 設定的入帳服務錢包（非零地址）。
2. 期別狀態為開放且 `now < cutoff`。
3. 本桶未停用、全域未停收。
4. 這張待付單的雜湊沒有用過（I6）。
5. 簽名還原出的地址為玩家，且玩家不在黑名單。
6. 金額 = 張數 × 該期每注金額；張數 ≤ 每筆上限。
7. 未入帳餘額（`USDT.balanceOf(Pool)`）≥ 金額，且未超過入帳上限。
8. 通過 → 標記待付單已用 → `Vault.bindReferrer(player, order.referrer)` → 寫入柱單（方式 ②），依綁定結果累加 `totalStake` 與第一、二層推廣應得 → `Vault.depositFromPool(asBet = true)`，USDT 立即轉入 `Vault`（I7）。
9. 發出事件，內含 `txRef`（轉帳交易編號），供後台告警逐筆比對。

> `txRef` 由入帳服務提供，合約無法驗證，只寫進事件讓任何人核對（架構 3.6 說明的唯一信任環節）。

## 4. 預言機合約 `Oracle`

### 4.1 簽名內容

`(chainId, poolAddress, officialNo, drawTime, numbers[5])`，以一般訊息簽名；TRON 訊息前綴格式【實作查證 V1】。

### 4.2 功能

| `verifyAndStore(pool, id, numbers, drawTime, sigs[])` | `Pool.submitResult` | 至少 2 個不同的簽名者簽同一內容；5 個號碼互不相同且都在 1–39 → 記錄結果、開始 30 分鐘爭議窗口 |

## 7. 安全要求（審計重點）

1. 1.3 的全域不變式 I1–I8 必須寫成自動化測試，並在每個測試案例結束時檢查。
2. 對外呼叫 USDT 一律用 1.2 的寫法。
3. 權限邊界：`Pool` 只能動自己那一桶的戶頭與平台戶（I2、I3）；`Vault` 只接受已啟用的 `Pool` 呼叫；建期參數只能來自 `setParams`。
4. 公開函式（`evaluate`、`distribute*`、`refund`、`retryReserve`、`pushAutoReturn` 等）必須在沒有工作可做時立即結束，不耗費多餘 energy。
5. 所有迴圈都有上限 n，不存在「一次處理整期」的迴圈（含推廣夥伴分潤）。
6. 時間判斷一律用區塊時間；`now < cutoff` 的邊界以「嚴格小於」為準。
7. 上線前由第三方審計公司審計，審計報告公開。
