# 實作對照：A6 無主款認領

> 狀態：**✅ 靜態原型完成**（`dashboard/admin.html` #page-a6）
> 規格來源：`05_前後台功能規格.md` §3.2 A6

---

## UI 元素清單

| 元素 | 類型 | 說明 | 規格來源 |
|---|---|---|---|
| 無主款列表 | 表格 | txHash、金額、入帳時間、狀態（待認領 / 申請中 / 已認領 / 待清理）| §A6 |
| 認領申請按鈕 | 按鈕 → 表單 | 客服填入申請人地址與簽名 | §A6 認領申請 |
| 簽名驗證結果 | 狀態顯示 | 後端驗證玩家用原轉帳錢包的簽名，顯示通過 / 不通過 | §A6 |
| 產生待簽交易按鈕 | 按鈕 | 驗證通過後，管理員發起認領 | §A6 / §3.4 |
| 30 天清理提示 | 條件顯示 | 快到 30 天時標示警告 | §A6 |
| 清理按鈕 | 按鈕 → 待簽交易 | 超過 30 天未認領 → 發起清理，等待 48 小時 | §A6 |

## 排除清單（明確不做）

| 項目 | 原因 |
|---|---|
| 客服直接轉款 | 後台帳號沒有合約權限，一律走待簽交易（§3.1） |
| 不驗簽名直接認領 | 規格明確要求驗證原轉帳錢包的簽名 |

## API 欄位對照

| UI 顯示 | API 欄位 | 端點 | 備註 |
|---|---|---|---|
| 無主款列表 | `txHash`, `amount`, `receivedAt`, `status`, `expiresAt` | `GET /admin/api/unclaimed` | |
| 提交認領申請 | `txHash`, `claimantAddress`, `signature` | `POST /admin/api/unclaimed/:txHash/claim` | 後端驗簽 |
| 驗證結果 | `valid`, `message` | 同上 Response | |
| 發起認領待簽交易 | `txHash`, `claimantAddress` | `POST /admin/api/unclaimed/:txHash/pending-tx` | 管理員操作 |
| 發起清理待簽交易 | `txHash` | `POST /admin/api/unclaimed/:txHash/cleanup-tx` | 超過 30 天 |

## 按鈕與操作

| 按鈕 | 可用條件 | 觸發動作 | 規格來源 |
|---|---|---|---|
| 認領申請 | 客服 / 管理員 | 開啟表單，填地址 + 簽名 → 後端驗簽 | §A6 |
| 確認認領 | 管理員 + 驗簽通過 | 產生待簽交易 | §A6 / §3.4 |
| 發起清理 | 管理員 + 超過 30 天 | 產生待簽交易，48 小時後生效 | §A6 / §3.4 |
