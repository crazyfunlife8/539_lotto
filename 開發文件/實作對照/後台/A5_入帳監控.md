## 代為入帳 UX 說明

依 `04_智能合約規格.md` §2.4b：入帳服務停擺超過 `RELAYER_FALLBACK`（6 小時）後，管理多簽可呼叫相同的合約入帳函式（`creditTransferDeposit` / `Pool.creditUnmatched`），限制與 relayer 相同（D7 入帳上限等）。

**按鈕狀態**：
- 永遠顯示於服務狀態卡片，不隨停擺狀態消失
- 入帳服務**正常運作中**：按鈕停用（disabled），tooltip 說明「需入帳服務停擺超過 6 小時才可操作」
- 入帳服務**停擺超過 6 小時**：按鈕啟用，醒目顯示（橙色 / 紅色）

**代為入帳 Modal**（服務停擺時才可開啟）：

| 欄位 | 說明 | API 欄位 |
|---|---|---|
| 待處理交易 txHash | 從「待付單」Tab 選取，或手動貼上 | `txHash` |
| 所屬期號 | 從「待付單」資料自動帶入 | `drawNo` |
| 來源地址 | 從「待付單」資料自動帶入 | `address` |
| 下注號碼 | 管理員從對應柱單或玩家填入 | `numbers[]` |
| 確認送出 | 產生待簽交易 | `POST /admin/api/deposit-monitor/manual-register` |

> 注意：代為入帳同樣受 D7 入帳上限限制，後端應回傳 400 若超限。

## 排除清單（明確不做）

| 項目 | 原因 |
|---|---|
| 直接退款操作 | 異常款一律轉入餘額，不直接退回（§CLAUDE.md ② 補充） |
| 刪除紀錄 | 所有入帳紀錄不可刪除（審計需要） |

| UI 顯示 | API 欄位 | 端點 | 備註 |
|---|---|---|---|
