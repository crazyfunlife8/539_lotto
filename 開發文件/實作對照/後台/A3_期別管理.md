## Modal 詳細設計

### 查看開獎 Modal（狀態：已結算 或 爭議中 時可按）

| 欄位 | 說明 |
|---|---|
| 期號 | 唯讀，標題列顯示 |
| 開獎號碼 | 5 顆號碼球排列（官方最終結果）|
| Oracle 對照表 | 三列，各代表一台預言機 |

Oracle 對照表欄位：

| 欄位 | API 欄位 | 說明 |
|---|---|---|
| 預言機編號 | `oracles[].id` | #1（主）/ #2（備）/ #3（備）|
| 回報時間 | `oracles[].reportedAt` | 台灣時間 |
| 回報號碼 | `oracles[].numbers[]` | 5 顆號碼，與開獎號碼對比標色 |
| 比對結果 | `oracles[].match` | ✓ 符合（綠）/ ✗ 不符（紅）/ — 未回報（灰）|

### 爭議裁定 Modal（狀態：爭議中 且 管理員角色）

> ⚠️ **規格衝突（待確認）**：  
> - `05_前後台功能規格.md` §A3 API 欄位記載：`finalNumbers[]`（管理員提供最終號碼）  
> - `04_智能合約規格.md` §4.2：`resolve(pool, id, accept)` — accept 為 boolean，維持原結果或否決，**不接受新號碼輸入**  
> - 目前以合約規格為準（boolean）；若業主決定由後台提供最終號碼則需調整合約  

Modal 設計（以合約規格為準）：

| 元素 | 說明 |
|---|---|
| 期號（唯讀） | 標題列 |
| 爭議原因說明 | 顯示哪台預言機提交了不同結果 |
| Oracle 對照（唯讀）| 同查看開獎 modal 的對照表 |
| 確認裁定按鈕 | `accept: true` → 維持現有結果，進入可結算狀態 → 待簽交易 |
| 否決裁定按鈕 | `accept: false` → 否決，3 台須重新一致提交 → 待簽交易 |

## API 欄位對照

| UI 顯示 | API 欄位 | 端點 | 備註 |
|---|---|---|---|
| 期別列表 | `drawNo`, `pool`, `status`, `closingAt`, `ticketCount`, `totalBet` | `GET /admin/api/draws` | 支援分頁 |
| 開獎號碼 | `numbers[]` | `GET /admin/api/draws/:drawNo` | |
| 預言機回報 | `oracles[].id`, `oracles[].numbers[]`, `oracles[].reportedAt`, `oracles[].match` | 同上 | |
| 手動建立 | `drawNo`, `pool` | `POST /admin/api/draws` → 產生待簽交易 | |
| 取消 / 延期 | `drawNo`, `action` (`cancel`/`postpone`), `newClosingAt`（延期用） | `POST /admin/api/draws/:drawNo/pending-tx` | 後端驗證截止前 |
| 爭議裁定 | `drawNo`, `finalNumbers[]` | `POST /admin/api/draws/:drawNo/pending-tx` | |

## 按鈕與操作

| 按鈕 | 可用條件 | 觸發動作 | 規格來源 |
